## Design Context

### Users

The primary user is the owner of this Apple Silicon workstation. They use the page while choosing a local model for coding, technical research, summaries, image work, speech transcription, or experiments. The page should replace repeated searches across model cards, benchmark sites, terminal output, and old notes.

### Brand Personality

Practical, comprehensive, and clear. The page should feel like a maintained technical field guide: evidence-led, candid about limitations, and quick to scan without feeling like a generic software dashboard.

### Aesthetic Direction

Use a light editorial reference layout with strong typography, compact comparison tables, restrained green accents, and visible source links. Prefer broad page composition and information density over repeated cards. Avoid neon-on-dark styling, decorative gradients, glass effects, oversized marketing claims, and generic metric-card grids.

### Design Principles

1. Put the current installed inventory before historical results or setup instructions.
2. Make model choice possible from one row: best use, modalities, capabilities, context, local score, speed, memory, and runtime.
3. Clearly distinguish installed builds, tuned aliases, previously tested builds, and models that did not load.
4. Explain every score and technical term in plain language.
5. Keep the full guide usable by keyboard and readable at phone, tablet, normal desktop, and wide desktop widths.
